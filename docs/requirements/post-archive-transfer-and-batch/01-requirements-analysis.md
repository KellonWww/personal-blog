# 需求分析：文章双向转稿与批量管理

## 元数据
- 确认日期：2026-10-19
- 来源：本次对话，用户已确认推荐范围。

## 功能与边界
| 功能 | 规则 |
|---|---|
| 文章/草稿转私人档案 | 复制标题、Markdown 正文与分类/标签，保留原文章及状态 |
| 私人档案转文章 | 复用现有转草稿和关联审阅流程，原档案保留 |
| 防重复 | 同一文章 ID 只建立一份转存档案；重试返回已有档案，不覆盖档案编辑 |
| 批量管理 | 转档、发布、撤回草稿、删除、替换分类、替换标签 |
| 选择范围 | 当前页勾选，全选仅当前页；翻页/筛选/刷新清空选择，每批最多 50 篇 |
| 危险操作 | 执行前二次确认；分类/标签是整体替换，空列表明确表示清空 |
| 私密保护 | 档案关联稿只能从私人档案关联记录逐篇审阅发布，不允许普通入口/批量绕过 |

## 数据规则
- 转档生成独立文本快照，不建立自动同步；再次转档只跳过，不刷新旧副本。
- 已发布文章转档不会自动下线；要隐藏公开原文，需另行撤回草稿。
- 私人档案不复制公开文章摘要、封面和统计字段；原文章完整保留这些数据。
- 私人档案转文章沿用标题/正文复制，不复制私有分类、标签及来源身份。
- 档案限制沿用：标题 200 字、正文 100000 字、分类 10 项、标签 20 项；不截断超限数据。
- 已转存但被软删除的档案不自动重建；已删除文章不能转存。
- 单批任一校验失败均取消整批写入；请求结果不明时先刷新核对，不宣称必定失败。

## 技术约束
- 复用现有导入批次、档案版本、私有词表与公开审阅门禁，不新增数据库迁移。
- 转档来源：provider=blog，namespace=post-copies，docId=原文章 ID。
- 档案 ID 由来源与文章 ID 稳定生成，唯一约束阻止并发重复建档。
- 数据库读取按选中文章集合批量查询，不循环查询单篇文章。
- 每批在同一 D1 batch 事务内检查源版本并提交，分类标签使用集合写入。
- 管理员权限、CSRF、私有 no-store/noindex 响应沿用并覆盖新接口。
- 档案迁移与人工操作接口由用户自行执行，AI 不执行任何数据库写入。

## 验收标准
1. 草稿转档后仍可在文章管理找到原草稿；已发布原文状态不变。
2. 重复转档、网络重试及并发转档均不能产生重复档案或覆盖已有档案修改。
3. 当前页全选与逐项选择可批量操作，翻页后不携带隐形选择。
4. 混入档案关联稿的批量发布整批拒绝；发布后的关联稿须先撤回才能改分类标签。
5. 任一文章版本变化、无效分类标签或事务中途失败，整批不部分提交。
6. 私人档案转草稿后，经既有审阅确认方可公开；删除原文章不删除独立档案。
7. 编译、静态检查通过；真实数据库写入、并发及浏览器验收由用户人工执行。
