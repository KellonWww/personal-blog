## 2. 页面与数据流

沿用 DESIGN.md、AdminShell 和现有双主题，不重做公开站，不新增搜索服务或身份体系。

| 入口 | 行为 |
|---|---|
| /admin/archives | 私有列表、正文搜索、来源/分类/标签筛选、冲突提示 |
| /admin/archives/:id | Markdown 阅读/编辑、来源、历史、文本差异、恢复、冲突处理、文本导出、主动转稿 |
| /admin/imports/:id | 新增/跳过/更新/冲突/失败逐项报告；未归档资源引用单独提示，不算附件已保存 |
| 本地 CLI | 只读 manifest 与 Markdown；预检及人工确认后提交文本，不扫描、打开或上传图片/附件 |

~~~mermaid
flowchart LR
  A[本地 manifest 与 Markdown] --> B[CLI 文本预检]
  B --> C[牢大人工确认导入]
  C --> D[Hono 管理员门禁与 CSRF]
  D --> E[D1 私有正文与不可变版本]
  E --> F[检索、编辑、历史与文本导出]
~~~

私有数据不进入静态 props、公开 API/搜索、RSS、sitemap、相关文章或前台统计。

## 3. 文本导入与引用边界

1. 抽取现有 manifest/Markdown 解析纯函数；只接受 manifest 和合法 UTF-8 Markdown，不新增其他文档格式解析。
2. source-key 必填且跨目录稳定；身份为 provider＋namespace＋manifest 原始 doc_id，禁止按标题、路径或清洗 ID 去重。source_url 无可靠元数据则为空并报告。
3. 指纹覆盖规范化标题、正文、来源分类标签；保存原始 Markdown 文本及其哈希、解析器版本。附件字节变化不检测、不形成新版本；正文中的引用字符串变化属于正文变化。
4. 原始 Markdown 文本保存在不可变来源版本中，阅读副本可清洗；不宣称保存原文件的编码/BOM/文件属性，不宣称附件归档或完整灾备。
5. --preflight 不写 D1、不联网抓资源、不扫描附件；输出身份碰撞、文本错误、动作预测和未归档资源引用。需要比较现状时通过管理员只读接口批量取基线。
6. --apply 仅由牢大审核后人工运行；复用短期管理员会话及 CSRF，凭据不进参数日志/仓库；接口只能连明确配置的可信站点，鉴权失败停止并允许原 runId 重试。
7. manifest 缺失/损坏或身份重复整批失败；单篇文本缺失、坏编码或路径越界逐项失败并继续，汇总非零退出。仅附件未归档不使正文导入失败，报告明确“仅保存文本，资源未归档”。
8. 文本路径做 realpath/symlink 与备份根校验；不读根外文件，不根据 Markdown 链接读取本地图片、普通文件或远程 URL。
9. 固定 runId＋itemKey 幂等；每篇独立事务，断点重试不重复建档/版本。基线查询默认每批 50 项，按 D1 参数及请求体上限调整；分页与有界单篇提交不做全库大事务。
10. 来源消失只报告“本次未见”，不删档、不撤稿；新 CLI 不调用旧 public 图片复制和公开文章写入逻辑。旧脚本保留历史用途，不作为私人导入入口。
11. 原始正文中的图片/附件引用保留为文本；私有预览默认不加载图片、不内嵌 HTML/iframe/SVG/PDF，不把本地相对资源路径映射到站点 public。
12. 引用只显示转义后的说明/地址；合法 http(s) 链接由用户主动点击，在新页打开并禁止 referrer/opener；本地、未知协议及主动内容不执行，不自动抓取。差异和搜索片段一律文本转义。

## 4. 编辑、冲突、检索与发布

### 4.1 三方基线与历史

B＝上次接受的来源快照；L＝当前工作版本；S＝本次来源快照；比较完整可编辑文本及元数据快照。

| 条件 | 行为 |
|---|---|
| 首次同源 doc_id | 新建私有档案及初始来源版本，current＝acceptedSource＝latestSource |
| S＝latestSource | 无新版本；已有冲突继续显示，不重复建候选 |
| S≠latestSource 且 L＝B、无冲突 | 新增来源版本，同时推进工作头、已接受基线与来源头 |
| S≠latestSource 且 L≠B，或已有冲突 | 保存来源候选及最新来源指针，不覆盖工作头或已接受基线 |
| 新来源恰好等于本地 | 保存来源事件、关联来源版本并推进基线，不抹掉来源历史 |
| 用户解决冲突 | 保留本地/接受来源/手工合并均追加 resolution 版本，并明确接受最新来源作为下次基线 |

所有编辑、恢复、导入、解决冲突使用 expectedVersion/expectedHead，过期返回 409；来源又变时不能解决旧候选后静默接受过时基线。
A→B→C、A→B→A 均保留来源历史，不按永久 archive＋hash 唯一去重。恢复复制目标快照新增版本并记录 restoredFrom，不回退序号或自动改导入基线。
提供任意两版本行级文本差异、操作者、原因、来源及时间；版本和差异必须校验属于同一档案。

### 4.2 正文检索与导出

- 沿用上轮官方资料核查的 D1 FTS5 方向，不引入外部检索服务；trigram、中文/代码、短词及片段仍须在隔离 D1 实测后定版。
- 标题与可读正文建立工作版本索引，保留代码块文本；三字符以上词用参数化、字面量转义的 MATCH，1～2 字用参数化 instr 回退，多词 AND。
- 来源/分类/标签在同一查询中筛选后排序分页；返回安全片段。历史及冲突候选只在详情中查，不混入默认搜索。
- 索引通过触发器或同事务更新，可由基础文本重建；不做异步最终一致。FTS 的共享库备份影响仍是上线门禁。
- 只导出所选版本 Markdown＋metadata.json，含来源身份/URL、版本引用、哈希、导入时间及“资源未归档”声明；无 includeAttachments、资源下载或附件包。
- CLI 可将鉴权取得的文本写到用户指定的仓库外目录；这属于文本导出，不新增服务端文件存储。没有全库、完整历史、账号或站点配置灾备承诺。

### 4.3 主动转博客与权限

- 用户选择工作快照后只创建 draft，档案仍私有；私有来源、分类标签、历史不自动公开，博客分类标签重新选择。
- 草稿预览列明正文及全部资源引用；本地/不可解析资源引用必须移除或由用户替换为已有公开 URL 后才能发布。本期无代传、转存或自动修图功能。
- 外链图片/文件不抓取、不承诺可用性，用户必须确认它们会成为公开引用；不得把鉴权档案 API、私有地址或本地路径当公开资源发布。
- 档案关联稿的普通文章发布入口也必须进入统一确认门禁，不能绕过 publications/confirm；确认事务校验预览时的文章版本/内容哈希、引用清单及幂等键，过期 409。原独立博客文章保持原发布语义。
- 首次转稿须原子绑定 post 与 publication；确认写入同事务做条件更新，不能“先查版本再无条件发布”。来源更新不自动改公开文章，重试不重复建稿。
- 私有页面 SSR 与全部档案 API 显式 requireAdmin；匿名 401、普通用户 403；写请求复用 CSRF。页面/API/导出及错误响应 private, no-store，不把正文/凭据写入日志。

## 5. 数据模型与迁移影响

独立 archive_*，不向 posts 加 private 状态、不混用公开分类标签；复用 users、sessions、D1。以下是模型草案，不是可执行 SQL。

| 实体 | 关键字段与约束 |
|---|---|
| archive_sources | provider、namespace/source_key、display_name、base_url；UNIQUE(provider, namespace) |
| archives | source_id、source_doc_id、source_url/path、current/accepted_source/latest_source_version_id、conflict_state、first/last_imported_at；UNIQUE(source_id, source_doc_id) |
| archive_versions | archive_id、sequence、parent_id、kind、title、content_md、plain_text、metadata_snapshot_json、content/source/raw_hash、raw_content_md（来源版本）、restored_from、based_on_source、operation_id；UNIQUE(archive_id, sequence)、UNIQUE(operation_id) |
| archive_taxonomy | kind、name、normalized_name；UNIQUE(kind, normalized_name) |
| archive_taxonomy_links | archive_id＋taxonomy_id 联合主键；仅工作版本投影，历史分类标签在快照内 |
| archive_import_runs/items | 两表：来源/状态/时间/计数；item 的 doc_id、动作、版本、错误码、简短原因、重试状态；UNIQUE(run_id, doc_id) |
| archive_publications | archive_id、version_id、post_id、operation_id、draft/published、confirmed_at/by、确认版本/内容哈希/引用清单；幂等并可追溯 |
| archive_search | FTS5 派生索引：archive_id UNINDEXED、title、body |

不建 archive_assets/archive_version_assets，不存 object_key、附件 bytes 或附件哈希。实体沿用现有 SQLite 公共字段，关系表沿用既有规范；不可变快照禁止普通更新/软删，FTS 不加业务公共字段。
单篇 D1 batch 完成 CAS、版本、工作/来源头、词表投影、索引及导入结果；CAS 零行必须让事务失败或所有关联写入条件化为零。指针及版本归属需校验；约束冲突可重试，不能静默覆盖。
实现前确定 Markdown/版本快照/API 请求的体积上限、每页上限及差异最大行数；超限逐项报错，不无限读取或把大文件塞进数据库。

### 5.1 迁移与回滚

**⚠️ 需牢大审核后人工执行。** 确认后仅提供 migrations/ 与 migrations/rollback/ 下的迁移、只读校验及回滚草案，不执行 DDL/DML。
1. 迁移前盘点线上文章 ID/status/content 指纹及既有公开资源引用，备份 D1 并验证恢复；不要求开通对象存储，不改原 0001/0002、不重跑 seed。
2. 增量新增档案表/约束及索引，不搬旧文章、不改变旧权限；新增代码兼容后才开放入口，不修改既有媒体路径或增加 R2 配置。
3. FTS 独立迁移，由牢大在隔离库验证 trigram/中文/短词/事务/索引维护/导出恢复；失败回到方案，不静默变成标题搜索或引入外部服务。
4. 沿用上轮已记录的虚拟表导出风险：演练“暂停写入→备份全部基础表→隔离恢复→重建 FTS→校验”；不假定按表导出一定绕过限制，不删线上索引换备份。
5. 无真实档案写入时可退应用，再人工按依赖逆序移除新增对象；已有写入则关闭档案入口并保留所有文本/版本。存在档案关联稿时保留发布安全门禁，或暂停后台文章写入，不能退回可绕过确认的发布入口。
6. 导入撤销按 runId 出候选清单，已有档案以补偿新版本恢复；后续有编辑/发布只报冲突。既有公开文章、图片不随导入回滚删除。

0005 审计迁移为当前应用启用前置：版本读取也依赖 request_hash/change_reason 新列。编辑/恢复/解决冲突按 operationId + 请求哈希幂等，复用键异参返回 409；reason 随不可变版本追加。所有新增版本校验来源存活，resolution 事务内校验 pending 与最新来源候选；回滚应用时保留审计列及保护触发器。

0006 转稿迁移同样是启用前置：新增 request_hash/archive_sequence，原子新建私有草稿并校验当前工作快照；已有来源冲突时禁止转稿。转稿只复制标题/正文，提供 GET archives/:id/publications 分页核对。
当前分批实现暂不提供 confirm：0006 一律拦截关联稿发布/换绑/硬删除与 REPLACE，关联永久保留。后续确认能力须用审核迁移替换该临时封锁，不能简单移除保护；迁移前若已有 published 关联稿则停止人工审核。

### 5.2 接口与代码影响

以下新增接口均挂 /api/admin/ 并显式 requireAdmin；路由→services→db，复用 Zod、会话、CSRF 及错误信封。

| 接口族 | 契约要点 |
|---|---|
| GET archives、archives/:id、archive-taxonomy、archive-sources | q/source/category/tag、分页、正文安全片段、当前版本与冲突状态 |
| POST/PATCH archive-taxonomy；PATCH archives/:id | 私有词表、正文及分类标签编辑；expectedVersion、过期 409 |
| GET versions、versions/:id、diff；POST restore、resolve | 归属校验、文本差异、追加版本、乐观锁及最新来源校验 |
| GET/POST imports、imports/:id/items | 只读批量基线、批次/逐项幂等提交及报告；服务端重新判定冲突，不信任 CLI 结论 |
| GET archives/:id/export?versionId=版本ID | 必须指定版本；Markdown attachment，来源名称/地址为导出时现值；不含原始来源文本或附件，不是完整灾备 |
| POST archives/:id/blog-draft、publications/:id/confirm | 幂等键、原子转稿关联、预览版本/哈希/引用清单；普通文章入口同步保护关联稿 |

差异接口 GET archives/:id/diff?from=版本ID&to=版本ID：返回标题/分类标签前后值及纯文本逐行差异，前端只用文本节点。每端最多 2000 行，裁去公共前后缀后矩阵最多 1000000 单元；超限返回 422 DIFF_TOO_LARGE，提示分别导出，不截断伪装完整差异。末尾换行以末尾空行表示。

管理页只展示纯文本，不渲染 Markdown/HTML 或自动请求资源。保存结果不明时保留原请求及幂等键重试；未保存草稿/未知请求触发离开提醒。来源与私有词表分页加载，不把首 50 项当作全量。

改动 app 路由挂载、新 db/services/types、AdminShell 导航、后台组件及 SSR 页面、新文本导入 CLI；文章写入补档案关联稿确认门禁。不新增存储配置、不扩展媒体上传下载；既有公开查询不 UNION 档案。

## 6. 分阶段计划与验收

| 阶段 | 交付与门禁 |
|---|---|
| P0 | 确认文本版方案；核对真实 manifest 格式、来源命名空间和文本体积上限 |
| P1 | 私有鉴权、数据模型/迁移回滚草案、隔离 D1 检索与备份恢复人工演练 |
| P2 | 文本预检/报告、幂等、三方冲突与断点恢复，使用合成资料 |
| P3 | 正文检索、管理编辑、历史差异/恢复、文本导出及现有双主题适配 |
| P4 | 转稿/确认发布、普通文章入口门禁、回归；完成类型检查/构建/lint，记录未验证项 |

| 验收组 | 必须通过 |
|---|---|
| 无对象存储 | 不配置 R2 或其他文件存储，新档案全流程可用；CLI 不读/复制/上传附件，服务端不调用桶 |
| 引用处理 | 含图片/文件链接仍能导入正文并提示未归档；私有预览无自动资源请求，无本地路径映射，危险协议不执行 |
| 重复与更新 | 同源 ID 不重复建档、换目录身份不变、正文更新及 A→B→A 留历史；附件字节单独变化不承诺检测 |
| 冲突与故障 | L/S/B 均保留；重跑不叠加候选；过期请求 409；单篇失败/断点重试不丢失或重复创建 |
| 正文检索 | 正文/代码、中文、1～2 字、多词及来源标签组合可检索；编辑/恢复后索引立即一致 |
| 历史与导出 | 差异转义；恢复新增版本可追溯；导出文本/来源准确，明确不含附件及完整灾备 |
