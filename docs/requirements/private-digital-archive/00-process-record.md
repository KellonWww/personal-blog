## 变更日志

- 时间：2026-10-19（Asia/Shanghai）。
- 级别：L3 方案级变更；由存原文/附件对象收缩为仅在 D1 保存 Markdown 文本及元数据。
- 原因：牢大不想维护图片、文件，且没有购买对象存储服务。
- 影响：删除附件表/接口/复制上传/对象哈希/附件版本/资源导出/公开转存/R2 配置；原文件对象改为来源版本的原始 Markdown 文本字段。
- 保留：文本导入、编辑、私有检索、历史/冲突、文本导出与主动转博客；原博客文章与图片不动。
- 已写代码改动量：本需求尚未编码，业务代码无需返工；只更新方案与现状的范围说明。
- 处理方式：当前处于方案阶段，回退方案评审；文件维护本期排除，不以换其他存储或塞二进制进 D1 变相实现。

## 局部复评与门禁

- v0.1 同桶回滚 P0：新档案不再写任何对象存储，原私有附件链路退出范围；旧媒体接口风险作为既有事实保留，不宣称已修复。
- v0.1 发布入口 P1：v0.2 要求所有档案关联稿发布统一确认、事务内 CAS，并补回滚发布门禁；仅设计闭环，代码尚未实现。
- 文本/来源版本保留在 D1；本地图片与文件不扫描、不读取、不复制、不托管，不以“归档完成”暗示资源已备份。
- 隔离 D1 的 FTS/trigram/中文短词、备份恢复、OAuth/角色、导入会话及文本体积上限仍是待验证项。
- 牢大确认 v0.2 后才进入 P1；不得将需求收缩或“接着干”解释为数据库写入授权。

## 执行红线

- 不擅改已有文章公开状态，不把导入等同于发布或持续同步；不删除已有 public 资源。
- 数据库结构/数据变更仅给迁移、只读校验及回滚草案，牢大人工审核执行。
- 不提交、不推送 Git；不对真实私人备份做试验性导入。
- 早期方案轮次仅文档；本轮实现及构建结果见 05，不将静态检查通过等同于功能验收。
